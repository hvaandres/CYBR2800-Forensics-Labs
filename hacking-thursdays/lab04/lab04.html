Lab Overview

In Labs 1 and 2, you learned how to acquire, preserve, verify, and examine digital evidence. You also recovered deleted files and examined filesystem metadata and system artifacts.

In this final lab, you will act as a digital forensic investigator.

Your goal is no longer simply to find individual files. Instead, you must determine:

What happened on the system, when did it happen, how did it happen, and what evidence supports your conclusion?

You will use the evidence image from the previous labs to build a timeline, correlate multiple artifacts, reconstruct the most likely sequence of events, and produce a professional forensic report.

Learning Objectives

By completing this lab, you should be able to:

  1. Create a forensic timeline from filesystem metadata.
  2. Identify important timestamps associated with files.
  3. Correlate filesystem activity with system and application logs.
  4. Identify suspicious user activity.
  5. Reconstruct a sequence of events from multiple evidence sources.
  6. Distinguish facts from assumptions.
  7. Document evidence using forensic best practices.
  8. Explain the limitations of forensic evidence.
  9. Develop an evidence-supported incident timeline.
  10. Produce a professional digital forensic report.

Important Lab Rules

Authorized Evidence Only: Use only the instructor-provided forensic evidence image.

Do not investigate your personal computer, another student's computer, or any system for which you do not have authorization.

All analysis must be performed on a working copy of the evidence. Do not modify the original evidence image.

Part 4 — Generate a Filesystem Timeline

The Sleuth Kit includes a tool called fls that can produce filesystem metadata information.

First, identify the filesystem:

fsstat CYBR2800_Lab3_Evidence.dd

Generate a recursive filesystem listing in bodyfile format: 

fls -r -m / CYBR2800_Lab3_Evidence.dd > timeline/filesystem_bodyfile.txt

Review the results:

less timeline/filesystem_bodyfile.txt

Search for specific users or files when appropriate: 

grep -i "alex" timeline/filesystem_bodyfile.txt

Search for potentially important files:

grep -Ei "password|credential|investigation|maintenance|suspicious|backup" \
timeline/filesystem_bodyfile.txt

Record important observations in your investigation notes.

Part 5 — Create a Human-Readable Timeline

Use mactime to convert the filesystem metadata into a human-readable timeline. 

mactime -b timeline/filesystem_bodyfile.txt > timeline/filesystem_timeline.txt

Open the timeline:

less timeline/filesystem_timeline.txt

Search for relevant users, filenames, or indicators: 

grep -i "alex" timeline/filesystem_timeline.txt

Search for potentially important files:

grep -Ei "password|credential|investigation|maintenance|suspicious|backup" \
timeline/filesystem_timeline.txt

What Are You Looking For?

Do not simply search for suspicious filenames. Look for relationships between events.

For example:

File Created
     ↓
File Modified
     ↓
User Command
     ↓
Network Activity
     ↓
File Deleted

Your goal is to determine whether the timestamps and artifacts support a sequence of activity.

Part 6 — Understand File Timestamps

Digital forensic investigations frequently rely on filesystem timestamps. The meaning and availability of timestamps can vary depending on the filesystem and forensic tool.

Common filesystem timestamp concepts
Timestamp Description
Modified Indicates when file contents were modified.
Accessed Indicates when a file was accessed, depending on filesystem behavior.
Changed Indicates when filesystem metadata changed.
Birth / Creation Indicates file creation time when supported and available.

Part 7 — Investigate User Activity

Review the user's shell history. First locate the file: 

fls -r CYBR2800_Lab3_Evidence.dd | grep bash_history

Identify the inode associated with the file.

Use istat to examine the inode:

istat CYBR2800_Lab3_Evidence.dd <INODE>

Extract the file:

icat CYBR2800_Lab3_Evidence.dd <INODE> > output/bash_history.txt

Review the extracted content:

cat output/bash_history.txt

Look for commands involving:

  • sudo
  • ssh
  • wget
  • curl
  • chmod
  • rm
  • cp
  • mv
  • Credential files
  • Configuration files
  • Scripts
  • Network-related commands

For each important command, identify where possible:

  • What command was executed?
  • What file or system resource was affected?
  • When did related filesystem activity occur?
  • Is there another artifact that supports the activity?

Part 15 — Build the Activity Sequence

Based on your evidence, reconstruct the most likely sequence of activity.

Your sequence may resemble: 

Initial Access
      ↓
Authentication
      ↓
User Activity
      ↓
File/System Activity
      ↓
Network Activity
      ↓
Possible Data Access
      ↓
Cleanup / Deletion

Do not assume that every stage occurred.

If you cannot prove that an event occurred, classify it using one of the following confidence levels:

  • Confirmed: Direct evidence supports the event.
  • Probable: Multiple pieces of evidence strongly support the event.
  • Possible: Evidence suggests the event, but it cannot be confirmed.
  • Unsupported: There is insufficient evidence to make the claim.

Part 17 — Identify What You Cannot Determine

Professional investigators must identify limitations in their findings.

Create:

notes/limitations.md

Consider the following questions:

  • Can you determine the exact person who used the account?
  • Can you prove that a source IP belonged to a specific person?
  • Can you determine whether a file was actually opened?
  • Can you prove that a suspicious script executed?
  • Can you determine whether data was exfiltrated?
  • Are timestamps alone sufficient to establish intent?

For each question, answer: Yes, No, or Cannot Determine.

Then explain why.

Investigator's Challenge

For the final part of the lab, imagine that you are presenting your findings to someone who has never taken a cybersecurity course.

You should be able to explain the investigation without simply saying:

"The log says this, so that's what happened."

Instead, explain the relationship between multiple sources of evidence:

"The log shows X. The filesystem shows Y. The user activity shows Z. Because these independent pieces of evidence occur within the same timeframe, the evidence supports the conclusion that..."

This is the difference between finding artifacts and conducting a forensic investigation.

Final Investigator Question

If this were a real incident rather than a classroom exercise, what additional evidence would you collect before making a final determination?

Think like a professional investigator. The goal is not to prove your theory. The goal is to determine what the evidence can actually support.
