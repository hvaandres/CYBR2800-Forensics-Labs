Digital Forensics Lab 2: Evidence Examination, Recovery, and Artifact Analysis

Course: CYBR 2800
Lab: 2 of 3
Estimated Time: 3–5 hours
Points: 100

Lab Purpose

In this lab, you will continue the forensic investigation from Lab 1. You will examine a preserved forensic disk image, identify files and directories, investigate deleted files, recover evidence, examine metadata, analyze user activity, and begin correlating evidence to determine what happened.

Learning Objectives

By completing this lab, you should be able to:

  • Verify the integrity of a forensic evidence image.
  • Work from a forensic copy without modifying the original evidence.
  • Identify the partition and file-system structure of a forensic image.
  • Use The Sleuth Kit command-line tools to examine files and directories.
  • Identify deleted files and recover deleted evidence.
  • Use file metadata to identify important forensic information.
  • Analyze user activity and system artifacts.
  • Search recovered evidence for relevant keywords and indicators.
  • Document evidence using hashes, screenshots, notes, and command output.
  • Begin developing an evidence-based explanation of the incident.

Scenario

You are continuing an investigation involving a workstation used by an employee named Alex. During the initial evidence-preservation process, a forensic disk image was created.

Your task in this lab is to examine the preserved image and determine whether there are indicators of suspicious activity.

You are specifically interested in:

  • Authentication activity
  • Remote connections
  • Command-line activity
  • Potentially suspicious scripts
  • Deleted files
  • Potentially exposed credentials
  • Connections to internal systems
  • Evidence that can help establish a timeline

Important: Protect the Evidence

Never modify the original forensic image.

You must create a working copy and perform your analysis against the working copy. Your original evidence image must remain unchanged.

Part 1: Install Required Tools and Prepare Your Forensic Workspace

If you are using a fresh Ubuntu VM (one that was not already set up in a previous lab), install The Sleuth Kit before continuing. sha256sum, strings, and grep are already included with Ubuntu. 

sudo apt update
sudo apt install sleuthkit

Verify that the tools are available:

which img_stat
which mmls
which fsstat
which fls
which istat
which icat
which tsk_recover
which sha256sum
which strings
which grep

Each command should print a file path. If any command prints nothing, re-run sudo apt install sleuthkit and try again before continuing.

Create a dedicated directory for this investigation:

mkdir -p ~/CYBR2800_Lab2/{evidence,working,recovered,output,screenshots,notes}

Move or copy your instructor-provided image into the evidence directory.

cp /path/to/CYBR2800_Lab2_Evidence.dd ~/CYBR2800_Lab2/evidence/

Change to your investigation directory:

cd ~/CYBR2800_Lab2

Part 2: Verify the Evidence Hash

Before beginning your examination, calculate the SHA-256 hash of the evidence image. 

sha256sum evidence/CYBR2800_Lab2_Evidence.dd

Compare the resulting hash with the SHA-256 value provided by your instructor.

Record the result:

sha256sum evidence/CYBR2800_Lab2_Evidence.dd > output/original_hash.txt

Evidence Requirement

Your report must explain whether the calculated hash matches the instructor's original hash.

Part 3: Create a Working Copy

Do not perform your investigation directly against the original evidence file. Create a working copy. 

cp evidence/CYBR2800_Lab2_Evidence.dd working/CYBR2800_Lab2_Working.dd

Calculate the hash of the working copy:

sha256sum working/CYBR2800_Lab2_Working.dd

The working copy should initially have the same SHA-256 hash as the original. 

sha256sum working/CYBR2800_Lab2_Working.dd > output/working_hash.txt

Why Do We Hash the Working Copy?

Hashing allows you to demonstrate that the working copy initially matched the evidence you received. This is an important part of documenting evidence integrity.

Part 4: Examine the Forensic Image

Use img_stat to examine the image:

img_stat working/CYBR2800_Lab2_Working.dd

Save the output:

img_stat working/CYBR2800_Lab2_Working.dd > output/img_stat.txt

Identify and record:

  • Image type
  • Image size
  • Sector size, if displayed
  • Other relevant image information

Part 5: Identify the Partition Structure

Run:

mmls working/CYBR2800_Lab2_Working.dd

Save the results:

mmls working/CYBR2800_Lab2_Working.dd > output/mmls.txt

Identify the partition containing the file system you need to analyze. Record the Start sector for that partition.

You will use this value as the -o offset in later Sleuth Kit commands.

Important

Do not blindly copy an offset from another student's work. Use the partition information displayed by mmls on your own evidence image.

Part 6: Examine the File System

Replace OFFSET below with the partition start sector identified with mmls. 

fsstat -o OFFSET working/CYBR2800_Lab2_Working.dd

Save the results:

fsstat -o OFFSET working/CYBR2800_Lab2_Working.dd > output/fsstat.txt

Identify:

  • File-system type
  • Block or cluster information
  • Inode or metadata information
  • File-system creation information, if available
  • Other information relevant to your investigation

Part 7: List Files and Directories

Use fls to examine the directory structure. 

fls -o OFFSET working/CYBR2800_Lab2_Working.dd

Now perform a recursive listing: 

fls -r -o OFFSET working/CYBR2800_Lab2_Working.dd

Save the complete listing:

fls -r -o OFFSET working/CYBR2800_Lab2_Working.dd > output/file_listing.txt

Review the listing and identify files that may be relevant to the investigation.

Part 8: Investigate Deleted Files

Deleted files are particularly important in digital forensics because users may attempt to remove evidence by deleting files.

Use:

fls -r -d -o OFFSET working/CYBR2800_Lab2_Working.dd

Save the results:

fls -r -d -o OFFSET working/CYBR2800_Lab2_Working.dd > output/deleted_files.txt

Carefully review the output and identify the deleted files associated with the investigation.

Questions

  1. How many deleted files did you identify?
  2. What are their names?
  3. Where were the files located?
  4. Which deleted file appears most relevant to the investigation?
  5. Why could deleted files be important evidence?

Part 9: Examine File Metadata

Once you identify a potentially important file, use istat to examine its metadata.

The output from fls will provide a metadata address for the file. Use that address with istat. 

istat -o OFFSET working/CYBR2800_Lab2_Working.dd META_ADDRESS

Save the output:

istat -o OFFSET working/CYBR2800_Lab2_Working.dd META_ADDRESS > output/important_file_istat.txt

Look for information such as:

  • File type
  • File size
  • Metadata address
  • Creation or change information, when available
  • Modification time
  • Access time
  • Deletion information
  • Data blocks associated with the file

Part 10: Recover a Deleted File with icat

Select one deleted file that is relevant to the investigation.

Use icat to recover its contents. 

icat -o OFFSET working/CYBR2800_Lab2_Working.dd META_ADDRESS > recovered/recovered_file.txt

Examine the recovered file:

cat recovered/recovered_file.txt

Calculate its SHA-256 hash:

sha256sum recovered/recovered_file.txt

Save the hash:

sha256sum recovered/recovered_file.txt > output/recovered_file_hash.txt

Evidence Documentation

Document:

  • Original file name
  • Original location
  • Metadata address
  • Recovery method
  • Recovered file name
  • SHA-256 hash
  • Important information discovered inside the file

Part 11: Recover Files Automatically

Use tsk_recover to recover files from the evidence image. 

mkdir -p recovered/tsk_recover
tsk_recover -o OFFSET working/CYBR2800_Lab2_Working.dd recovered/tsk_recover

Review the recovered directory: 

find recovered/tsk_recover -type f

Search the recovered files: 

grep -Rni "backup" recovered/tsk_recover

You should also search for:

grep -Rni "password" recovered/tsk_recover
grep -Rni "10.10.20.25" recovered/tsk_recover
grep -Rni "10.10.20.55" recovered/tsk_recover
grep -Rni "ssh" recovered/tsk_recover

Do Not Assume Every Result Is Malicious

A forensic analyst must distinguish between evidence and conclusions. A suspicious-looking command, IP address, or file does not automatically prove malicious activity.

Your conclusions should be supported by multiple pieces of evidence whenever possible.

Part 12: Analyze User Activity

Review the recovered files for evidence of user activity.

Pay particular attention to:

  • .bash_history
  • .browser_history.txt
  • .ssh/config
  • Documents
  • Scripts
  • Authentication logs
  • Network activity logs

Search for commands involving SSH:

grep -Rni "ssh" recovered/tsk_recover

Search for network addresses:

grep -Rni "10.10.20." recovered/tsk_recover

Search for potentially relevant tools:

grep -RniE "curl|wget|scp|nc|netcat" recovered/tsk_recover

Investigation Questions

  1. Which user appears to have performed the activity?
  2. Which systems were accessed?
  3. Which IP addresses appear repeatedly?
  4. Were there failed authentication attempts?
  5. Were there successful authentication attempts?
  6. What commands were executed?
  7. What files appear to be associated with the activity?

Part 13: Analyze the Suspicious Script

Locate the maintenance.sh file in the evidence.

Display its contents:

cat recovered/tsk_recover/home/alex/Documents/maintenance.sh

If the recovered directory structure differs, use find to locate it: 

find recovered/tsk_recover -name "maintenance.sh" -print

Analyze the script and answer:

  1. What does the script attempt to do?
  2. What remote IP address does it reference?
  3. What tools or commands does it use?
  4. Does it download another file?
  5. Where would the downloaded file be stored?
  6. What evidence would you want to investigate next?

Part 14: Search for Indicators

Conduct a broader search of the recovered evidence.

Search for the suspicious IP address:

grep -Rni "10.10.20.55" recovered/tsk_recover

Search for the backup server:

grep -Rni "10.10.20.25" recovered/tsk_recover

Search for credential-related information:

grep -RniE "password|credential|username|login" recovered/tsk_recover

Document the files that produced relevant results.

Part 15: Examine File Metadata Using Linux Tools

For recovered files that are available in the normal Linux file system, you may also use the stat command. 

stat recovered/tsk_recover/home/alex/Documents/maintenance.sh

Compare the information returned by stat with the forensic metadata returned by istat.

Question

What is the difference between examining a recovered file using normal operating system tools and examining the original file-system metadata using a forensic tool such as istat?

Part 20: Write Your Preliminary Findings

Write a preliminary investigation summary of approximately 500–750 words.

Your summary should include:

  • What you investigated
  • How the evidence was preserved
  • How you verified the evidence
  • Important artifacts discovered
  • Deleted files recovered
  • Important user activity
  • Important network indicators
  • Your current interpretation
  • Limitations of your investigation
  • Recommended next steps

Professional Writing Guidance

Avoid statements such as "Alex definitely hacked the server" unless the evidence proves that conclusion.

Instead, describe what the evidence demonstrates. For example: "The evidence indicates that an SSH connection was established from 10.10.20.10 to 10.10.20.25 during the documented time period."

Separate observations from interpretations.

Important Forensic Principle

Digital forensics is not simply about finding something suspicious. Your job is to establish what the evidence actually shows, preserve that evidence, document your methodology, and clearly distinguish facts from assumptions.

In the next lab, you will use the artifacts discovered here to build a timeline, correlate multiple pieces of evidence, determine what most likely occurred, and produce a professional forensic investigation report.
